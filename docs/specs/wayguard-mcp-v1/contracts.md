# Contracts — wayguard-mcp-v1

- **Spec:** `tasks/context/wayguard-mcp-v1/spec.md`
- **Manifest:** `docs/specs/wayguard-mcp-v1/manifest.md`
- Phases append their produced interfaces under "Phase contracts". Line refs are to the spec.

## Applies to all phases

- CON-001 (L400-402) — only the five MCP tools exist; no shell tool, ever.
- CON-002 (L403-405) — no `shell=True`, `os.system`, `os.popen`, `eval`, `exec`, or string-built local commands; CI static check (AC-014 L498-500), first enforced in phase 1.
- CON-003 (L406-407) — in `serve`, stdout carries JSON-RPC only; all logging to stderr.
- CON-004 (L408-409) — stdio transport only; never bind a socket.
- CON-005 (L410-412) — fail closed: every error path in loading, validation or runner yields denial/error, never execution.
- CON-006 (L413-415) — no secret egress in results, errors, audit or stderr (keys, ssh config, `SSH_AUTH_SOCK`, env dumps, `ssh -G` output).
- CON-007 (L416-417) — pinned version ranges, committed `uv.lock`, nothing fetched at runtime; set up in phase 1.
- CON-008 (L418-419) — Linux and macOS, Python 3.11+; no Windows; CI matrix from phase 1.
- CON-009 (L420-423) — hard ceilings are module constants (timeout 120 s, 256 KiB/stream, 2,000 lines/stream, concurrency 8); nothing can raise them.
- Concurrency and idempotency (L425-432) — `flock` for audit, UUID4 + `O_EXCL` for proposals, multiple `serve` processes may share state.
- REQ-001 atomic-write rule (L113-114) — temp file in same dir, fsync, `os.replace`; dirs `0700`, files `0600`.

## Phase contracts

### Phase 1

- **Tooling:** `uv` (`uv sync --locked`); `.python-version` 3.12; `requires-python >=3.11`; build backend hatchling, src layout. Run: `uv run pytest`, `uv run ruff check`, `uv run mypy --strict src/`, `uv run python scripts/check_static_safety.py src`. Dev deps in `[dependency-groups] dev`. Runtime dep: `mcp>=1.2,<2` (add others with pinned ranges, re-run `uv lock`).
- **Entry point:** console script `wayguard-mcp` -> `wayguard.cli:main(argv: Sequence[str] | None = None) -> None`; `python -m wayguard` works. Phase 1 CLI is a stub (`--version`, help); later phases extend `build_parser()`/`main` in `src/wayguard/cli.py` (exit codes still to be fixed in phase 2).
- **CI:** `.github/workflows/ci.yml`, matrix ubuntu-latest/macos-latest x Python 3.11/3.12; steps: locked sync, ruff, mypy strict, static check, pytest.
- **Static check (AC-014):** `scripts/check_static_safety.py DIR...` (AST-based; flags `eval(`, `exec(`, `os.system`, `os.popen`, any `shell=` keyword other than literal False); exit 1 on hit. Tested in `tests/test_static_safety.py`.
- **`wayguard.config`:**
  - Ceilings (CON-009): `MAX_TIMEOUT_SECONDS=120`, `MAX_STREAM_BYTES=256*1024`, `MAX_STREAM_LINES=2000`, `MAX_CONCURRENCY=8`; `DIR_MODE=0o700`, `FILE_MODE=0o600`.
  - `default_root() -> Path` = `<passwd home of current UID>/.config/wayguard` (ignores `$HOME`, XDG, CWD). Every other function takes `root: Path` explicitly so tests use `tmp_path`.
  - `policy_path(root)`, `audit_path(root)` (`audit.jsonl`), `proposals_dir(root)`, `state_dir(root)`.
  - `ensure_layout(root)`: creates root, `proposals/`, `state/` at 0700, tightens existing.
  - `atomic_write(path, data: bytes, mode=0o600)`: mkstemp in same dir, fchmod, fsync, `os.replace`, fsync dir; temp removed on failure, original untouched.
  - `check_policy_file(path, root) -> Path` (resolved): raises `PolicyPermissionError` (message contains "missing", "regular", "symlink", "owner", or "writable") if missing, non-regular, symlink resolving outside root, wrong UID, or group/other-writable. Callers must treat any raise as denial (CON-005).
  - `class PolicyPermissionError(Exception)`.

### Phase 2

- **No new dependency**: structural validation is hand-written in `wayguard.policy` (spec suggested `jsonschema`; not used). `tests/__init__.py` added; tests import `tests.test_policy.good()` as a valid-policy fixture.
- **Policy schema (v1)**: top-level `{version, defaults, servers}` all required. `defaults`: `decision`("deny"), `timeout_seconds`, `max_output_bytes`, `max_concurrent_actions` all required, >0, within config ceilings. Server: required `enabled`(bool), `ssh_alias`, `actions`; optional `description`(<=200). Action: required `description`(<=500), `risk`("read-only"), `executable`, `args`, `parameters`(may be `{}`); optional `timeout_seconds`, `max_output_bytes` (<= defaults). Param types: `integer{minimum,maximum}`, `enum{values}`, `string{max_length 1-256,pattern 1-256 chars, compilable}`; forbidden: raw/shell/command/script/args_extra. Placeholder = arg exactly `{name}`, name `[A-Za-z_][A-Za-z0-9_]{0,63}`. Duplicate JSON keys, NaN/Infinity, non-UTF8 rejected. Alias allowlist `[A-Za-z0-9_.@:+-]`, first char not `-`, <=255.
- **`wayguard.policy` public API** (all frozen dataclasses): `Policy(defaults, servers: Mapping[str, Server], sha256, path, loaded_at)` with `get_enabled_server(id) -> Server|None`; `Defaults(timeout_seconds, max_output_bytes, max_concurrent_actions)`; `Server(id, enabled, ssh_alias, description, actions)`; `Action(id, description, risk, executable, args: tuple[str,...], parameters: Mapping[str, ParameterSpec], timeout_seconds, max_output_bytes)` (timeout/cap already EFFECTIVE = action value or default; hard ceilings enforced at load so runner need only clamp with config constants as defense in depth); `ParameterSpec(name, type, minimum, maximum, values, max_length, pattern)` (match with `re.fullmatch`).
- **Functions**: `parse_policy(data: bytes, path=None) -> Policy`; `load_policy(root) -> Policy` (raises `config.PolicyPermissionError` then `PolicyInvalidError`; both = denial); `policy_changed_since_load(policy) -> bool` (re-hash file; unreadable => True); `string_value_violation(value, max_length) -> str|None` (REQ-004 runtime string rules; phase 3 MUST reuse for agent strings); `is_denied_executable(path)`; `has_control_chars(s)`; constants `DENYLIST`, `MAX_ERRORS=50`, `MAX_PATTERN_LENGTH=256`.
- **`PolicyInvalidError.errors: list[str]`**: each `"<json.path>: <fixed reason>"` (e.g. `servers.prod.actions.tail.executable: executable is on the interpreter denylist`); key names escaped to `[A-Za-z0-9_.-]`, `?` otherwise, truncated to 40; max 50 entries; never contains policy values. Phases 3/6 should use the same style for denial reasons and `get_policy_status.errors`.
- **CLI exit codes (README documented)**: `cli.EXIT_OK=0, EXIT_INTERNAL=1, EXIT_INVALID_POLICY=2, EXIT_DENIED=3, EXIT_OPERATIONAL=4`. `PolicyPermissionError`/missing policy => 3; invalid => 2; unknown `--server` => 3; init-without-force and OSError => 4; unexpected exception => 1 with a fixed "internal error" message.
- **CLI**: `cli.main(argv) -> int` now RETURNS the exit code (console script and `python -m wayguard` do `sys.exit(main())`). Subcommands: `init [--force]` (backup `policy.json.bak-<UTC stamp>`, mode 0600), `policy validate`, `actions list [--server ID]` (never prints ssh_alias). CLI obtains root via module-level `cli.default_root` (tests monkeypatch it); later phases must do the same. `SAMPLE_POLICY` in `cli.py`.
- Remaining for later phases: `doctor` (7), line-cap truncation stub test (4).

### Phase 3

- **Modules**: `wayguard.validation` (request validation, audit-sink contract) and `wayguard.command` (argv + remote command, ssh discovery, child env). Pure; no process spawned, no I/O except `os.stat`/passwd lookups.
- **`validation.validate_request(policy: Policy | None, raw: object) -> ValidatedRequest`**; raises `RequestDenied(code, reason)`. Order: policy (None => `policy_invalid`), object shape / extra top-level field, server, enabled, action, missing params, extra params, per-param checks. `ValidatedRequest(server, action, params)`; `params` is a read-only `MappingProxyType` copy (ints real ints, never bool). Strings go through `policy.string_value_violation` + `re.fullmatch(pattern)` + UTF-8 encodability; enums exact membership.
- **Reasons**: `"<json.path>: <fixed reason>"` (paths `server_id`, `action_id`, `parameters.<name>`, `request`, `policy`); param/field key names sanitized like policy `_safe_key` (`[A-Za-z0-9_.-]`, else `?`, max 40); agent values never echoed. `RequestDenied.code` / `.reason`.
- **Reason codes (`validation.REASON_CODES`, shared vocabulary, extend by appending)**: `policy_invalid`, `invalid_request` (non-object / missing or non-string id / non-object parameters), `extra_field`, `unknown_server`, `server_disabled`, `unknown_action`, `missing_parameter`, `extra_parameter`, `invalid_parameter`. Phases 4-6 add e.g. `concurrency_limit`, `proposal_limit`, runner statuses (not re-using these).
- **`validation.AuditSink` Protocol** (keyword-only args): `record_denied(correlation_id, server_id|None, action_id|None, params_summary, reason_code)`; `record_start(correlation_id, server_id, action_id, params_summary)`; `record_end(correlation_id, server_id, action_id, params_summary, status, exit_code|None, duration_ms, stdout_bytes, stderr_bytes, truncated, timed_out)`. Phase 5 implements it (event values `start`/`end`/`denied`, add `ts` itself). Sinks should not raise into the denial path.
- **`validation.authorize_request(policy, raw, sink, correlation_id) -> ValidatedRequest`**: validate; on denial calls `sink.record_denied` exactly once (ids only if they match `policy.ID_RE`, else None; params via `normalize_params`) then re-raises `RequestDenied`. Phase 6 MCP tool should call this; runner calls `record_start/end` with `normalize_params(v.params, v.action.parameters)`.
- **`validation.normalize_params(params, specs=None) -> dict`**: ints as-is, strings `{len, sha256_8}`, bools/other `{"type": <name>}`; enum strings kept as-is only when `specs` says enum (validated); at most 64 keys; keys sanitized.
- **`command.TRUSTED_SSH_PATHS`** = `("/usr/bin/ssh","/usr/local/bin/ssh","/opt/homebrew/bin/ssh")` hard-coded.
- **`command.discover_ssh(*, _candidates=TRUSTED_SSH_PATHS) -> str`**: first absolute path that is a regular file (symlinks followed) and executable; else `SshNotFoundError` (fail closed). **Test seam**: only the keyword-only `_candidates` parameter; no env var, policy key or MCP input can reach it. Production calls `discover_ssh()` bare. Runner (phase 4) should accept an already-resolved `ssh_path` so tests pass a fake ssh path directly to `build_command`.
- **`command.child_env(environ=None) -> dict`**: exactly `HOME`/`USER`/`LOGNAME` (from passwd of current UID, not env), `LANG=C.UTF-8`, `PATH=/usr/bin:/bin`, plus `SSH_AUTH_SOCK` if set and non-empty in `environ` (default `os.environ`). Runner must pass this as the full child env.
- **`command.build_command(request: ValidatedRequest, ssh_path: str) -> BuiltCommand(argv: list[str], remote_command: str)`**; also `build_remote_command(action, params)`, `build_argv(ssh_path, server, action, remote_command)`. argv is the REQ-006 golden list (25 elements for ConnectTimeout=min(10, action.timeout_seconds); `--`, alias, remote command last). Re-checks (defense in depth): absolute ssh path, alias vs `ALIAS_RE`, string values vs `string_value_violation`, bool/int types; failures raise `CommandBuildError` (fixed messages). `remote_command` must never be logged/audited (REQ-011).
- **[RESOLVED phase 4: policy validator now rejects `minimum < 0` with `<path>: minimum must not be negative`]** ~~Known limitation~~: an `integer` parameter whose policy `minimum` is negative can yield an arg like `-5` (option-like for the remote program). Policy authors control this; the validator does not reject it (spec says "within range"). Consider a policy-load warning later.

### Phase 4

- **Extra fix**: `policy.parse_policy` rejects integer parameter specs with `minimum < 0` (reason `"<json.path>: minimum must not be negative"`). Resolves the Phase 3 known limitation.
- **`wayguard.redaction.redact(text: str) -> str`**: best-effort, replaces with `[REDACTED:<kind>]`; kinds `private_key` (also unterminated PEM to end of text), `authorization` (whole header value), `cookie` (Cookie/Set-Cookie value), `jwt`, `bearer`, `secret` (password|passwd|secret|token|api_key `=` value; key kept, value replaced), `aws_key` (AKIA/ASIA), `token` (ghp_/glpat-/sk-/xoxb-/xoxp-). Never claim completeness.
- **`wayguard.ssh_runner`** (async; phase 6 awaits it):
  - `async run_action(request: ValidatedRequest, *, ssh_path: str, correlation_id: str, sink: AuditSink | None = None, environ=None) -> RunResult`. `ssh_path` = absolute path from `command.discover_ssh()` (tests: `discover_ssh(_candidates=[stub])`). Spawns with default `shell=False`, `stdin=DEVNULL`, `env=child_env(environ)`, `start_new_session=True`. Calls `sink.record_start` then `sink.record_end` (exceptions from the sink are swallowed). Never raises for runner failures (they become `internal_error`); relative ssh path / `CommandBuildError` / spawn `OSError` -> `internal_error`, exit_code None.
  - **Cancellation hook**: cancel the asyncio task awaiting `run_action`; the child process group is SIGTERMed, SIGKILLed after grace, reaped, `record_end(status="cancelled")` is audited, then `CancelledError` propagates (phase 6 maps this to its MCP result; "cancelled" is an audit-only status, not a REQ-009 status).
  - **Timeout**: `effective_timeout(s)=clamp(1..120)`; SIGTERM to process group, `KILL_GRACE_SECONDS=2.0`, then SIGKILL the group (always), wait. Status `timeout`, `exit_code=None`, partial output kept.
  - **Caps**: per stream `effective_cap(max_output_bytes)=clamp(1..MAX_STREAM_BYTES)` and `MAX_STREAM_LINES` lines; excess is drained/discarded; `truncated_*` set; `*_bytes` = original byte count read; text gets trailing line `[wayguard: output truncated at N of M+ bytes (limit ...)]`. Decode UTF-8 `errors="replace"`, redact, then marker appended. Exit 0 with truncated output stays `ok` (flags tell the caller).
  - **`RunResult`** (frozen dataclass; phase 6 serializes): `status, correlation_id, server_id, action_id, exit_code (int|None), duration_ms, stdout, stderr (redacted), truncated_stdout, truncated_stderr, stdout_bytes, stderr_bytes, untrusted_output_notice`. `status` in `ssh_runner.STATUSES` (REQ-009 list; `denied`/`busy` are produced by phase 6, not the runner).
  - **`classify(exit_code, stderr, *, timed_out) -> str`**: timed_out -> `timeout`; None (killed by signal) -> `ssh_error`; 0 -> `ok`; 255 -> phrase match; other -> `nonzero_exit`. Phrases only matter for 255.
  - **`SSH_255_PHRASES`** (RESOLVED, first match wins, substring, case-sensitive): `host_key_error`: "Host key verification failed", "REMOTE HOST IDENTIFICATION HAS CHANGED"; `auth_error`: "Permission denied ("; `unknown_alias`: "Could not resolve hostname"; `unreachable`: "Connection refused", "Connection timed out", "No route to host", "Network is unreachable"; no match -> `ssh_error`.
  - **`format_text_block(result) -> str`**: `NOTICE` first, then `--- BEGIN UNTRUSTED REMOTE OUTPUT ---`, status line, `[stdout]`/`[stderr]` sections, `--- END UNTRUSTED REMOTE OUTPUT ---`; delimiter strings inside output are replaced with `[delimiter removed]`. Constants `NOTICE`, `BEGIN_DELIMITER`, `END_DELIMITER`.
  - **`ConcurrencyGate(limit)`**: `limit` clamped to `1..MAX_CONCURRENCY`; thread-safe non-blocking `try_acquire() -> bool`, `release()` (never below 0). Phase 6 owns one gate sized by `policy.defaults.max_concurrent_actions`, returns `busy` + `record_denied(reason_code=CONCURRENCY_LIMIT)` when `try_acquire()` is False, and must `release()` in a `finally`.
- **Reason code added**: `validation.CONCURRENCY_LIMIT = "concurrency_limit"` (in `REASON_CODES`).
- **Audit status values passed to `record_end`**: REQ-009 statuses plus `cancelled`.

### Phase 5

- **Audit event vocabulary (RESOLVED)**: `event` in `start` | `end` | `denied`. Every line has ALL keys: `ts` (UTC ISO-8601, ms), `event`, `correlation_id`, `server_id`, `action_id`, `params` (normalize_params output), `status`, `exit_code`, `duration_ms`, `stdout_bytes`, `stderr_bytes`, `truncated`, `timed_out`, `reason_code`; non-applicable = `null`. `start`: status null. `end`: status = REQ-009 status or `cancelled`. `denied`: `status="denied"`, `reason_code` = a `validation.REASON_CODES` value or `proposal_limit`. Phase 6 should also `record_denied` for `busy` (`concurrency_limit`) and `proposal_limit` denials (it may pass `server_id`/`action_id` None, `params_summary={}`).
- **`wayguard.audit`**: `FileAuditSink(root: Path)` implements `validation.AuditSink`; methods never raise (failures swallowed; `append(event)` is the raising primitive). `tail(root, limit=20) -> list[str]` raw lines; `prune(root, *, older_than_days>=1, now=None) -> int removed` (ValueError if <1; undatable lines are kept). Locking: `flock` on `state/audit.lock` (NOT the log, so prune's `os.replace` cannot orphan appenders); log opened `O_APPEND|O_NOFOLLOW`, 0600. Construct one sink per process: `FileAuditSink(config-root)`.
- **`wayguard.proposals`** (library for phase 6 `propose_action`): `create_proposal(root, *, server_id, goal, reason, suggested_action_summary=None, server_known: bool) -> str` (id). Validates lengths (server_id 1-256, goal<=500, reason<=1000, summary<=1000; strings only; all control chars except `\n` rejected) raising `ProposalInputError(.reason)` (fixed text, no value echo); at >=200 pending raises `ProposalLimitError` (`.code == "proposal_limit"`, `proposals.PROPOSAL_LIMIT`). Phase 6 computes `server_known` from the policy and does the tool-schema/extra-property check and the response text (id + `wayguard-mcp proposals show <id>`). Also `get_proposal`, `list_proposals(root, *, include_all=False)`, `set_status(root, id, "dismissed"|"done")` (CLI only; do NOT expose via MCP), `ID_RE` (strict lowercase UUID4), errors `InvalidProposalIdError`, `ProposalNotFoundError`, `ProposalStateError`.
- **Proposal concurrency guarantee**: cap check + `O_EXCL` create + every status change run under one exclusive `flock` on `state/proposals.lock`; the cap of 200 is exact among processes using this module on a local FS with flock. Not enforced against writers bypassing the module or on flock-less filesystems (small overshoot possible). Unparseable proposal files count as pending.
- **Proposal file**: `proposals/<uuid4>.json` 0600: `id, created_at, server_id, server_known, goal, reason, suggested_action_summary (null if absent), status`, plus `status_changed_at` after a transition. Reads use `O_NOFOLLOW`.
- **CLI**: `audit tail [--limit N>=1, default 20]` (raw JSONL lines), `audit prune --older-than DAYS>=1` (prints removed count; DAYS<1 / non-int = usage error exit 2), `proposals list [--all]`, `proposals show ID`, `proposals dismiss ID`, `proposals mark-done ID`. ID must match `proposals.ID_RE` before any path is built. Exit codes: malformed or unknown ID -> 3 (`EXIT_DENIED`), already-terminal status change -> 4 (`EXIT_OPERATIONAL`), OSError -> 4. Phase 6 `serve` should wire `audit.FileAuditSink` as the `AuditSink` for `authorize_request`/`run_action`.

### Phase 6

- **`wayguard.mcp_server`**: `create_server(root: Path, *, ssh_path: str | None = None) -> mcp Server` (loads policy once; `ssh_path` is the test seam, None => `command.discover_ssh()` per call; not reachable from env/MCP input); `WayguardService(root, *, ssh_path=None)` with `.policy` (None = deny-all), `.errors`, `.gate`, `async call_tool(name, arguments) -> CallToolResult`; `tool_definitions(policy)`; `serve(root) -> int` (logging to stderr, `sys.stdout` redirected to stderr after the stdio transport takes the real stdout). CLI: `wayguard-mcp serve` (root via `cli.default_root`).
- **Tool outputs** (all as `structuredContent` + text content; every result has `enforcement: "local-policy-only"`; `isError` stays false, check `status`): `list_servers` -> `{servers:[{server_id, description?, action_count}]}`; `list_actions` -> `{server_id, actions:[{action_id, description, risk, parameters:{name:{type,minimum/maximum|values|max_length,pattern?}}, timeout_seconds, max_output_bytes}]}`; `get_policy_status` -> `{schema_version:1, validation, errors[], loaded_at|null, policy_changed_since_load, enforcement}`; `run_action` -> RunResult fields (+ text via `format_text_block`) or `{status:"denied"|"busy", reason_code, reason, correlation_id}`; `propose_action` -> `{status:"recorded", proposal_id, review}` or denied (`invalid_request`, `proposal_limit`).
- **Audit**: run_action denials via `authorize_request`; busy -> `denied`/`concurrency_limit` (ids set, params `{}`); proposal cap -> `denied`/`proposal_limit` (ids null).
- **Deny-all errors**: permission/missing policy => `["policy: file is missing, unreadable or has unsafe permissions"]`; invalid => `PolicyInvalidError.errors`.
- `run_action` input schema `parameters` is an anyOf of per-action name sets with additionalProperties false; SDK input validation is off, `RequestDenied` handles all shape errors.

### Phase 7

- **`wayguard.doctor.run_doctor(root, *, ssh_candidates: Sequence[str] | None = None, out=print) -> int`**: `ssh_candidates=None` uses `command.TRUSTED_SSH_PATHS` (module attr `doctor.TRUSTED_SSH_PATHS`, monkeypatchable); tests pass a fake ssh list (the Phase 3 seam). CLI: `wayguard-mcp doctor` (calls it with `cli.default_root()`). Checks: python>=3.11, trusted ssh, modes of root/proposals/state (0700, no group/other bits) and policy.json (0600), policy load, per server `ssh -G -- <alias>` (argv, no shell, `child_env`, stdin/stdout/stderr DEVNULL, 10 s timeout) -> only `resolvable: yes|no` (aliases are never printed). Unresolvable alias is WARN (exit unaffected). Exit: 0 ok; 2 invalid policy; 3 policy missing/unsafe; 4 other failures (no ssh, bad modes, old Python). Policy failure code wins.
- **E2E**: `tests/test_e2e_docker.py` marked `e2e`; pyproject `addopts = -m "not e2e"` so it is deselected by default; run `uv run pytest -m e2e`. Skips if docker/ssh-keygen/ssh-keyscan missing.
